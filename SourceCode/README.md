# IT Helpdesk – ระบบแจ้งซ่อมและติดตามสถานะอุปกรณ์ไอที

> **ติดตั้งใช้งานจริง (Docker + HTTPS + สำรองข้อมูลอัตโนมัติ): ดู [DEPLOY.md](DEPLOY.md)**
> **ติดตั้งบน Windows (ไม่ใช้ Docker): ดู [DEPLOY-WINDOWS.md](DEPLOY-WINDOWS.md)**

เว็บแอปแจ้งซ่อมแบบตั๋ว (Ticket) ตามเอกสารโปรเจกต์: พนักงานแจ้งซ่อม ช่าง IT รับงานและอัปเดตสถานะ ผู้จัดการดูภาพรวม
และ Progress Bar บนหน้าจอพนักงาน/ผู้จัดการ **อัปเดตทันทีโดยไม่ต้องกด F5**

## เริ่มใช้งาน

ต้องใช้ Node.js 22.13 ขึ้นไป (ไม่ต้อง `npm install`)

```bash
npm start              # ใช้งานจริง: เปิดที่ http://localhost:3000
DEMO=1 npm start       # ลองเล่น: มีบัญชีและตั๋วตัวอย่าง (ดูด้านล่าง)
npm test               # ทดสอบ API และชั้นข้อมูล (58 รายการ)
```

### ผู้จัดการคนแรก (โหมดปกติ)

ครั้งแรกที่ฐานข้อมูลว่าง ระบบสร้างหมวดหมู่และผู้จัดการ 1 บัญชี **ไม่มีบัญชีหรือตั๋วตัวอย่าง** และไม่มีรหัสผ่านที่ใครเดาได้:

- ไม่ตั้งอะไร → ชื่อผู้ใช้ `admin` และ **รหัสผ่านสุ่มที่พิมพ์ในหน้าจอเทอร์มินัลครั้งเดียวเท่านั้น** (ถ้าลืมหรือไม่ทัน ให้รีเซ็ตด้วย `npm run reset-password -- admin` ที่เซิร์ฟเวอร์ ดู [DEPLOY.md](DEPLOY.md))
- หรือกำหนดเองครั้งแรก: `INITIAL_MANAGER_USERNAME=boss INITIAL_MANAGER_PASSWORD='รหัสผ่านยาว 8 ตัวขึ้นไป' npm start`
- ล็อกอินแล้วเพิ่มพนักงาน/ช่างได้จากเมนู “จัดการผู้ใช้” และเปลี่ยนรหัสผ่านตนเองได้จากแถบบน
- ถ้าฐานข้อมูลเดิมยังมีบัญชีที่ใช้รหัสผ่านสาธิต ระบบเตือนตอนเริ่มทำงาน ให้รีเซ็ตรหัสผ่านหรือปิดใช้งานบัญชีเหล่านั้น

### โหมดสาธิต (`DEMO=1`)

**ห้ามใช้กับระบบจริง** เพราะรหัสผ่านทุกบัญชีคือ `password123` และแสดงอยู่บนหน้าล็อกอิน:

| ชื่อผู้ใช้ | บทบาท |
|---|---|
| `somchai`, `suda` | พนักงาน |
| `tech1`, `tech2` | ช่าง IT |
| `manager` | ผู้จัดการ |

ลองดู real-time: เปิดสองหน้าต่าง (เช่น ปกติ + Incognito) ล็อกอินเป็น `somchai` กับ `tech1`
แล้วให้ช่างกด "เริ่มดำเนินการ" จะเห็นแถบสถานะฝั่งพนักงานเลื่อนเอง

## API (`/api/v1`)

| Method | Path | สิทธิ์ | หมายเหตุ |
|---|---|---|---|
| POST | `/auth/login` | ทุกคน | คืน JWT (หมดอายุ 8 ชม.), จำกัด 10 ครั้ง/นาที/IP |
| GET | `/auth/me` | ล็อกอินแล้ว | |
| POST | `/tickets` | ล็อกอินแล้ว | แนบรูปได้ ≤ 3 รูป (png/jpeg/webp/gif, base64) |
| GET | `/tickets?status=` | ล็อกอินแล้ว | พนักงานเห็นเฉพาะของตน; `pending` = `open` |
| GET | `/tickets/:id` | เจ้าของ/ช่าง/ผู้จัดการ | มีรูปและประวัติ |
| PATCH | `/tickets/:id/assign` | ช่าง, ผู้จัดการ | ช่างส่ง `{}` เพื่อรับงานเอง; ผู้จัดการส่ง `{assigneeId}` |
| PUT / PATCH | `/tickets/:id/status` | ช่าง, ผู้จัดการ | `{status, note?}` ลำดับ open → in_progress → resolved |
| POST | `/tickets/:id/notes` | ช่าง, ผู้จัดการ | `{text}` เพิ่มโน้ต ระบบประทับชื่อผู้บันทึกและเวลาเอง; ทำได้ทุกสถานะ (รวมหลังปิดงาน); ช่างทำได้เฉพาะงานของตนหรือที่ยังไม่มอบหมาย; ไม่เกิน 1000 ตัวอักษร/โน้ต, 100 โน้ต/ตั๋ว |
| DELETE | `/tickets/:id` | เจ้าของตั๋ว | เฉพาะสถานะ Open |
| GET | `/stats` | ผู้จัดการ | จำนวนตามสถานะ, First Response Time เฉลี่ย, ผลงานช่าง |
| GET | `/events` | ล็อกอินแล้ว | Server-Sent Events (real-time) |
| GET | `/categories`, `/users?role=` | ล็อกอินแล้ว / ช่าง,ผู้จัดการ | `/users` แสดงเฉพาะบัญชีที่ใช้งานอยู่ |
| GET | `/public/config`, `/public/categories` | ทุกคน | ข้อมูลตั้งต้นของหน้าแจ้งซ่อมสาธารณะ |
| POST | `/public/tickets` | ทุกคน (จำกัดต่อ IP) | `{name, contact, title, description, category, priority?, images?}` คืน `{no, trackToken}` |
| POST | `/public/track` | ทุกคน (จำกัดต่อ IP) | `{no, token}` คืนสถานะตั๋วที่เปิดเผยได้ (ไม่มีข้อมูลติดต่อ/รูป/รหัสแฮช) |
| POST | `/auth/password` | ล็อกอินแล้ว | เปลี่ยนรหัสผ่านตนเอง `{currentPassword, newPassword}` คืน token ใหม่ |
| GET / POST | `/admin/users` | ผู้จัดการ | รายชื่อผู้ใช้ทั้งหมด / เพิ่มผู้ใช้ `{username, name, role, password}` |
| PATCH | `/admin/users/:id` | ผู้จัดการ | แก้ `name`, `role`, `active` |
| POST | `/admin/users/:id/password` | ผู้จัดการ | รีเซ็ตรหัสผ่านให้ผู้อื่น `{password}` |

### แจ้งซ่อมโดยไม่ต้องสมัคร (ผู้แจ้งภายนอก)

คนที่ไม่มีบัญชีเข้าได้จากหน้าล็อกอิน (ปุ่ม “แจ้งซ่อมโดยไม่ต้องสมัคร”) หรือเปิด `/report.html` ตรง ๆ
กรอกชื่อ ช่องทางติดต่อ และอาการ (แนบรูปได้) แล้วระบบให้ **ลิงก์ติดตามสถานะ** กลับมา ไม่ต้องสมัครสมาชิก

- **ติดตามสถานะ:** เปิดลิงก์ `/track.html#no=…&t=…` จะเห็นแถบความคืบหน้า ผู้รับผิดชอบ และโน้ตจากช่าง อัปเดตเองทุก 10 วินาที
  ลิงก์เก็บไว้ในเบราว์เซอร์เครื่องที่แจ้ง (แสดงที่หน้าแจ้งซ่อม; เครื่องสาธารณะควรกด “ล้างรายการ”)
- **ฝั่งช่าง/ผู้จัดการ:** ตั๋วกลุ่มนี้ขึ้นพร้อมป้าย “ผู้แจ้งภายนอก” และช่องทางติดต่อกลับบนการ์ดตั๋ว
  ทำงานเหมือนตั๋วปกติ (รับงาน เปลี่ยนสถานะ โน้ต สถิติ) พนักงานทั่วไปมองไม่เห็นตั๋วกลุ่มนี้
- **ความปลอดภัย:** รหัสติดตามสุ่ม 128 บิต และระบบเก็บเฉพาะแฮช SHA-256 (กู้คืนให้ไม่ได้ ถ้าลิงก์หายต้องแจ้งใหม่
  หรือให้ช่างมอบหมายต่อจากตั๋วเดิม) รหัสส่งทาง POST และอยู่ใน `#` ของลิงก์จึงไม่ถูกส่งไปกับ request/log
  ตอบข้อความเดียวกันทั้งกรณีไม่มีเลขตั๋วและรหัสผิด
- **กันสแปม:** จำกัด 5 เรื่อง/10 นาที/IP และ 100 เรื่อง/ชั่วโมงทั้งระบบ, ช่อง honeypot ซ่อนไว้ดักบอต, จำกัดการค้นหา 60 ครั้ง/นาที/IP
  - หลัง reverse proxy ต้องตั้ง `TRUST_PROXY=1` ไม่เช่นนั้นทุกคนจะถูกนับเป็น IP เดียวกัน (ตั้งเฉพาะเมื่อมี proxy จริงเท่านั้น เพราะ header ปลอมได้)
  - ปิดฟีเจอร์ทั้งหมดได้ด้วย `ALLOW_GUEST=0`
  - ผู้ไม่หวังดีที่ส่งครบโควตารวมต่อชั่วโมงทำให้คนอื่นแจ้งไม่ได้ชั่วคราว ถ้าเป็นระบบภายนอกที่เสี่ยง ควรใส่ CAPTCHA เพิ่ม

### การจัดการผู้ใช้ (เมนู “จัดการผู้ใช้” สำหรับผู้จัดการ ปุ่ม “+ เพิ่มพนักงาน”)

- เพิ่มผู้ใช้ แก้ชื่อ เปลี่ยนบทบาท ปิด/เปิดใช้งาน และรีเซ็ตรหัสผ่าน; ทุกคนเปลี่ยนรหัสผ่านตนเองได้
- เปลี่ยนรหัสผ่าน เปลี่ยนบทบาท หรือปิดใช้งาน จะยกเลิก token เก่าทันที (ฟิลด์ `tokenVersion`) และตัดการเชื่อมต่อ real-time ของผู้ใช้นั้น
- ผู้จัดการลดสิทธิ์หรือปิดบัญชีตนเองไม่ได้ ส่วนช่างที่ยังมีงานค้างปิดบัญชีหรือเปลี่ยนบทบาทไม่ได้ จนกว่างานจะเสร็จหรือมอบหมายใหม่
- ไม่ลบผู้ใช้ แต่ปิดใช้งานแทน เพื่อให้ประวัติตั๋วและ log ยังอ้างอิงชื่อได้ครบ
- ทุกการกระทำถูกบันทึกใน collection `logs` (`user.created`, `user.updated`, `user.password_reset`, `user.password_changed`)

## โครงสร้าง

```
src/server.js   HTTP server, routes, RBAC, SSE
src/auth.js     JWT (HS256) + scrypt password hashing (node:crypto)
src/db.js       ชั้นข้อมูล SQLite (node:sqlite) ตาราง users, tickets, categories, logs เก็บที่ data/helpdesk.db
src/seed.js     ข้อมูลสาธิต
public/         หน้าเว็บ (HTML/CSS/JS ล้วน)
test/           ทดสอบ API
```

## จุดที่ต่างจากเอกสารโครงการ

- **ใช้ SQLite แทน MongoDB** และไม่ได้ใช้ Express / jsonwebtoken (ใช้ Node ล้วน ไม่ต้อง `npm install`)
  เหตุผล: ข้อมูลหลักเป็นโครงสร้างชัดเจนและมีการสรุปสถิติ ฐานข้อมูลเชิงสัมพันธ์จึงเหมาะกว่า
  ส่วนข้อมูลที่ยืดหยุ่น (รูปแนบ บันทึกจากช่าง รายละเอียดใน log) เก็บเป็นคอลัมน์ JSON
  - ใช้ `node:sqlite` ที่มีในตัว Node 22+ (ต้องใช้ Node 22.13 ขึ้นไปจึงไม่ต้องใส่แฟล็กพิเศษ; ยังเป็นฟีเจอร์ทดลองของ Node
    สคริปต์ `npm start` / `npm test` จึงปิดคำเตือน `ExperimentalWarning` ไว้)
  - `src/db.js` คงอินเทอร์เฟซแบบ collection (`insertOne`, `find`, `findOne`, `updateOne`, `deleteOne`) ไว้ จึงเปลี่ยนไปใช้
    ฐานข้อมูลอื่น (เช่น PostgreSQL) ได้โดยเขียน `Store` ตัวใหม่ (ต้องเปลี่ยนเป็น async)
  - ตารางมี `UNIQUE` (username, เลขตั๋ว), ดัชนีบน status/ผู้แจ้ง/ผู้รับผิดชอบ, โหมด WAL และเลขตั๋วเพิ่มแบบ atomic
  - **ย้ายข้อมูลจากเวอร์ชันก่อน:** ถ้ามี `data/db.json` และฐานข้อมูลใหม่ยังว่าง ระบบนำเข้าให้อัตโนมัติครั้งเดียว
    แล้วเปลี่ยนชื่อไฟล์เดิมเป็น `db.json.migrated` เก็บไว้สำรอง
  - **สำรองข้อมูล:** หยุดเซิร์ฟเวอร์แล้วคัดลอกโฟลเดอร์ `data/` ทั้งโฟลเดอร์ (รวมไฟล์ `-wal` และ `-shm`)
- **Real-time ใช้ Server-Sent Events** (ทางเดียว server → browser เพียงพอกับโจทย์นี้) ฝั่งเว็บใช้ fetch stream
  เพื่อส่ง JWT ทาง header ไม่ใส่ token ใน URL
- **สถานะ:** ใช้ PUT ตามเอกสาร และรองรับ PATCH ด้วย
- Collection `logs` เก็บประวัติทุกการกระทำ แสดงในรายละเอียดตั๋ว
- **โน้ตและการติดตามผู้รับงาน:** ปุ่ม “+ เพิ่มโน้ต” บนตั๋ว (ช่าง/ผู้จัดการ) บันทึกข้อความพร้อมชื่อและเวลาอัตโนมัติ
  พนักงานผู้แจ้งเห็นโน้ตสด ๆ ในรายละเอียดตั๋ว บนการ์ดตั๋วแสดงผู้รับผิดชอบ เวลารับเรื่อง และเวลาเสร็จ
  ส่วนประวัติเต็ม (ใครมอบหมาย/เปลี่ยนสถานะเมื่อไหร่) ดูได้ที่ “รูปภาพ/ประวัติ” — เวลาแสดงตามปฏิทินไทย (ปี พ.ศ. 2 หลัก เช่น 69 = 2569)

## HTTPS และความปลอดภัย

- ตั้ง `TLS_KEY` และ `TLS_CERT` (พาธไฟล์) เพื่อเปิด HTTPS พร้อม HSTS หรือรันหลัง reverse proxy ที่เป็น HTTPS
- อย่าเปิด `DEMO=1` บนระบบจริง และตรวจว่าไม่มีคำเตือนเรื่องรหัสผ่านสาธิตตอนเริ่มระบบ
- กุญแจเซ็นการล็อกอิน: ตั้งเองด้วย `JWT_SECRET` (ยาว 16 ตัวอักษรขึ้นไป) หรือไม่ต้องตั้ง ระบบสร้างและเก็บไว้ที่ `data/jwt-secret`
  (สิทธิ์ 600) ให้ ผู้ใช้จึงยังล็อกอินค้างอยู่หลังรีสตาร์ท ไฟล์นี้เป็นความลับ ห้ามแชร์หรือนำขึ้น Git
- ตัวแปรสภาพแวดล้อมอื่น: `DATA_DIR` (โฟลเดอร์ข้อมูล), `HOST`/`PORT`, `TRUST_PROXY=1` (อยู่หลัง reverse proxy), `ALLOW_GUEST=0` (ปิดหน้าแจ้งซ่อมสาธารณะ),
  `LOG_REQUESTS=0` (ปิด access log) และ `GET /healthz` สำหรับตรวจสุขภาพ
- สคริปต์ดูแลระบบ: `npm run backup`, `npm run restore -- <ไฟล์.db.gz>`, `npm run reset-password -- <ชื่อผู้ใช้>`
- ส่วนที่ทำไว้แล้ว: รหัสผ่านแฮช scrypt, ตรวจสิทธิ์จาก DB ทุกคำขอ, พนักงานเปิดตั๋วคนอื่นได้ 404,
  ตรวจชนิดไฟล์รูป, จำกัดขนาด body, CSP แบบเข้ม, กัน path traversal, เขียนข้อความด้วย `textContent` (กัน XSS)

## ข้อจำกัดของต้นแบบ

- SQLite เหมาะกับเซิร์ฟเวอร์เครื่องเดียว (รองรับผู้ใช้พร้อมกันหลักสิบถึงหลักร้อยได้สบาย) แต่ไม่เหมาะกับการรันหลายเซิร์ฟเวอร์
  แชร์ฐานข้อมูลเดียวกัน และ real-time (SSE) ก็ทำงานภายในโปรเซสเดียว ถ้าต้องขยายให้ย้ายไป PostgreSQL ร่วมกับ pub/sub
- รูปแนบเก็บเป็น base64 ในคอลัมน์ JSON ใช้งานจริงควรย้ายไป object storage
- ยังไม่มี refresh token, ระบบลืมรหัสผ่านทางอีเมล (ให้ผู้จัดการรีเซ็ตให้) และการลบผู้ใช้ถาวร
