# คู่มือติดตั้งใช้งานจริง (IT Helpdesk)

เอกสารนี้พาติดตั้งบนเซิร์ฟเวอร์ Linux ที่มีโดเมนของตัวเอง ใช้เวลาประมาณ 15–30 นาที
> ใช้ Windows? ดู [DEPLOY-WINDOWS.md](DEPLOY-WINDOWS.md) (ไม่ต้องใช้ Docker)

ติดตั้งแบบ Docker (แนะนำ) ได้ใน 6 ขั้นตอน และมีทางเลือกแบบไม่ใช้ Docker อยู่ท้ายเอกสาร

> **ข้อควรทราบ:** ไฟล์ติดตั้งส่วน Docker และ Caddy ผ่านการตรวจไวยากรณ์แล้ว (`docker compose config`)
> แต่ **ยังไม่เคยสร้างอิมเมจหรือออกใบรับรอง HTTPS จริง** เพราะสภาพแวดล้อมที่เตรียมไฟล์ไม่มี Docker daemon และอินเทอร์เน็ตสาธารณะ
> ตัวแอป สคริปต์สำรอง/กู้คืน และการปิด/เริ่มระบบทดสอบแล้วจริง ให้ลองติดตั้งบนเครื่องทดสอบก่อนใช้งานจริงหนึ่งรอบ

## สิ่งที่ต้องมี

- เซิร์ฟเวอร์ Linux (CPU 1 core, RAM 1 GB ก็พอสำหรับหลักสิบถึงร้อยคน) ที่ติดตั้ง [Docker](https://docs.docker.com/engine/install/) พร้อม Docker Compose v2
- โดเมนหรือซับโดเมน เช่น `helpdesk.mycompany.co.th` ที่ตั้ง DNS (A record) ชี้มาที่ IP ของเซิร์ฟเวอร์
- เปิดพอร์ต **80 และ 443** (ใช้ออกใบรับรอง HTTPS และให้บริการ) ส่วนพอร์ต 3000 ของแอปไม่ถูกเปิดออกนอกเครื่อง

## ติดตั้งด้วย Docker

1. **คัดลอกโปรเจกต์ไปที่เซิร์ฟเวอร์** (เช่น `/opt/helpdesk`) แล้วเข้าไปในโฟลเดอร์นั้น
2. **สร้างไฟล์ตั้งค่า**

   ```bash
   cp .env.example .env
   nano .env        # แก้ DOMAIN เป็นโดเมนจริง (บรรทัดอื่นใช้ค่าเริ่มต้นได้)
   ```

3. **เริ่มระบบ** (ครั้งแรกสร้างอิมเมจ ใช้เวลาสักครู่)

   ```bash
   docker compose up -d --build
   ```

4. **ดูรหัสผ่านผู้ดูแลระบบที่ระบบสุ่มให้** (แสดงครั้งเดียวเท่านั้น) ถ้าไม่ได้ตั้ง `INITIAL_MANAGER_PASSWORD` ไว้

   ```bash
   docker compose logs app | grep setup
   ```

5. **เปิดเบราว์เซอร์ไปที่ `https://โดเมนของคุณ`** ล็อกอินด้วยชื่อผู้ใช้ `admin` และรหัสผ่านจากข้อ 4
   แล้วกด “เปลี่ยนรหัสผ่าน” ที่แถบบนทันที (ถ้า HTTPS ยังไม่ขึ้น ดู `docker compose logs caddy` มักเป็นเรื่อง DNS ยังไม่ชี้มา หรือพอร์ต 80/443 ถูกบล็อก)
6. **ตรวจสุขภาพระบบ:** `docker compose ps` ต้องขึ้น `healthy` ที่ `app` และ `https://โดเมนของคุณ/healthz` ต้องตอบ `{"ok":true}`

## การใช้งานหลังติดตั้ง

| บทบาท | ทำอะไรได้ |
|---|---|
| **ผู้ดูแลระบบ (`admin`)** | บัญชีผู้จัดการคนแรก เพิ่ม/แก้/ปิดบัญชี รีเซ็ตรหัสผ่าน มอบหมายงาน ดูสถิติ |
| **พนักงาน** | ล็อกอินเพื่อแจ้งซ่อม ติดตามสถานะแบบสด และยกเลิกเรื่องที่ยังไม่มีคนรับ |
| **ช่าง IT** | รับงาน เปลี่ยนสถานะ เพิ่มโน้ต |
| **ผู้ไม่มีบัญชี** | แจ้งซ่อมได้ที่ `https://โดเมนของคุณ/report.html` ไม่ต้องสมัคร แล้วติดตามด้วยลิงก์ที่ได้รับ |

- **เพิ่มพนักงานใหม่:** ล็อกอินเป็น admin → เมนู “จัดการผู้ใช้” → ปุ่ม “+ เพิ่มพนักงาน” → เลือกบทบาท ตั้งรหัสผ่านเริ่มต้น
  แล้วแจ้งผู้ใช้ด้วยตนเอง (ไม่มีอีเมลอัตโนมัติ) ให้เปลี่ยนรหัสผ่านหลังเข้าครั้งแรก
- **ลิงก์สำหรับผู้ไม่มีบัญชี:** ประกาศหรือพิมพ์เป็น QR code ติดที่จุดบริการได้ ส่วนผู้ที่ปิดไม่ให้ใช้ ตั้ง `ALLOW_GUEST=0` ใน `.env` แล้ว `docker compose up -d`

## การสำรองข้อมูลและกู้คืน

ระบบสำรองฐานข้อมูลอัตโนมัติ **วันละครั้ง** (บริการ `backup`) เก็บย้อนหลังตาม `BACKUP_KEEP` (ค่าเริ่มต้น 14 ไฟล์) โดยไม่ต้องหยุดระบบ
ไฟล์สำรองทุกไฟล์ถูกตรวจความสมบูรณ์ก่อนนับว่าสำเร็จ

**สำคัญ:** ไฟล์สำรองอยู่ในเครื่องเดียวกับระบบ ถ้าเครื่องหรือดิสก์เสียจะหายไปพร้อมกัน ต้องคัดลอกออกไปเก็บที่อื่นเป็นประจำ เช่น

```bash
docker compose cp backup:/backups ./backups-copy      # คัดลอกออกมาที่โฟลเดอร์ปัจจุบัน
# แล้วส่งต่อไปเครื่อง/พื้นที่เก็บข้อมูลอื่น เช่น rsync หรือ rclone (ตั้งใน cron ของเครื่องแม่ให้ทำทุกวัน)
```

| งาน | คำสั่ง |
|---|---|
| สำรองทันที (เช่น ก่อนอัปเดต) | `docker compose exec backup node --disable-warning=ExperimentalWarning scripts/backup.js` |
| ดูรายการไฟล์สำรอง | `docker compose run --rm --no-deps backup ls -l /backups` |
| **กู้คืน** (ขั้นตอนด้านล่าง) | ดูต่อไปนี้ |

กู้คืน (ต้องหยุดแอปก่อน ฐานข้อมูลเดิมไม่ถูกลบ ระบบเก็บไว้ที่โฟลเดอร์ `pre-restore-…` ในข้อมูล):

```bash
docker compose stop app backup
docker compose run --rm --no-deps backup node --disable-warning=ExperimentalWarning scripts/restore.js /backups/helpdesk-<เวลา>.db.gz
docker compose up -d
```

> ควรลองกู้คืนบนเครื่องทดสอบสักครั้งก่อนเกิดเหตุจริง ไฟล์สำรองที่ไม่เคยลองกู้คืนอาจใช้ไม่ได้ตอนต้องการ

## การอัปเดตระบบ

1. สำรองทันที (คำสั่งในตารางด้านบน)
2. แทนที่ไฟล์โปรเจกต์ด้วยเวอร์ชันใหม่ (**อย่าลบ `.env`**) ข้อมูลอยู่ใน volume จึงไม่ถูกแตะ
3. `docker compose up -d --build` — ระบบรับสัญญาณปิดอย่างสุภาพ ผู้ใช้ที่เปิดหน้าเว็บไว้จะเชื่อมต่อใหม่เองภายในไม่กี่วินาที
   ถ้ามีการเปลี่ยนโครงสร้างฐานข้อมูล ระบบเพิ่มคอลัมน์ให้เองตอนเริ่มทำงาน

## ลืมรหัสผ่านผู้ดูแลระบบ

คนอื่นรีเซ็ตให้ไม่ได้ถ้าเป็นผู้จัดการคนเดียว ให้รีเซ็ตที่เซิร์ฟเวอร์ (ผู้ที่เข้าเซิร์ฟเวอร์ได้เท่านั้นทำได้):

```bash
docker compose exec app node --disable-warning=ExperimentalWarning scripts/reset-password.js admin
```

ระบบสุ่มรหัสผ่านใหม่และพิมพ์ให้ครั้งเดียว เปิดใช้งานบัญชีอีกครั้งหากถูกปิด และให้ทุกอุปกรณ์ของบัญชีนั้นล็อกอินใหม่
(กำหนดรหัสเอง: ใส่ `-e NEW_PASSWORD='...'` หลัง `exec`) การรีเซ็ตถูกบันทึกในประวัติระบบ

## เฝ้าระวังและดู log

- **สถานะ:** `docker compose ps` และ `https://โดเมนของคุณ/healthz` (นำไปตั้งให้ตัวเฝ้าระบบเช่น UptimeRobot ตรวจทุกนาทีได้)
- **log แอป:** `docker compose logs -f app` — บรรทัดละคำขอเป็น JSON (`t` เวลา, `m` วิธี, `p` พาธ, `s` สถานะ, `ms`, `ip`)
  ไม่บันทึก query string, header หรือรหัสผ่าน/โทเคนใด ๆ (ปิดได้ด้วย `LOG_REQUESTS=0`)
- **ดิสก์:** รูปแนบเก็บในฐานข้อมูล ตรวจพื้นที่ว่างเป็นระยะ (`docker system df`)

## เช็กลิสต์ก่อนเปิดใช้งานจริง

- [ ] เปลี่ยนรหัสผ่าน `admin` แล้ว และไม่ได้เปิด `DEMO=1` (ไม่มีบรรทัด `[warn]` ใน log ตอนเริ่ม)
- [ ] ถ้ากำหนด `INITIAL_MANAGER_PASSWORD` ใน `.env` — ลบบรรทัดนั้นออกแล้ว
- [ ] เปิดผ่าน `https://` ได้ และ `http://` ถูกส่งต่อไป https เอง
- [ ] ไฟร์วอลล์เปิดเฉพาะพอร์ต 22 (SSH), 80, 443 และพอร์ต 3000 เข้าจากภายนอกไม่ได้
- [ ] ตั้งการคัดลอกไฟล์สำรองออกไปนอกเครื่อง และ **ลองกู้คืนบนเครื่องทดสอบสำเร็จแล้วอย่างน้อยหนึ่งครั้ง**
- [ ] ตั้งตัวเฝ้าระบบที่ `/healthz` ให้แจ้งเตือนเมื่อระบบล่ม
- [ ] อัปเดตระบบปฏิบัติการและ Docker ของเซิร์ฟเวอร์เป็นประจำ
- [ ] แจ้งผู้ใช้ภายนอกที่ใช้หน้าแจ้งซ่อม ว่าเก็บชื่อและช่องทางติดต่อไว้เพื่อติดต่อกลับเรื่องซ่อมเท่านั้น
      (ข้อมูลเหล่านี้เป็นข้อมูลส่วนบุคคลตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล องค์กรควรมีนโยบายเก็บ/ลบข้อมูล ตัวระบบยังไม่มีฟังก์ชันลบข้อมูลตั๋วเก่า)

## ติดตั้งแบบไม่ใช้ Docker (systemd)

ต้องมี **Node.js 22.13 ขึ้นไป** (ตรวจด้วย `node -v` แพ็กเกจของบางดิสโทรเก่ากว่านี้ ให้ติดตั้งจาก NodeSource หรือ nvm)

```bash
sudo useradd --system --home /opt/helpdesk --shell /usr/sbin/nologin helpdesk
sudo mkdir -p /opt/helpdesk /var/lib/helpdesk
sudo cp -r package.json src public scripts /opt/helpdesk/
sudo chown -R helpdesk:helpdesk /var/lib/helpdesk

sudo tee /etc/helpdesk.env >/dev/null <<'EOF'
NODE_ENV=production
DATA_DIR=/var/lib/helpdesk
HOST=127.0.0.1
PORT=3000
TRUST_PROXY=1
EOF
sudo chmod 600 /etc/helpdesk.env

sudo cp deploy/helpdesk.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now helpdesk
sudo journalctl -u helpdesk | grep setup      # ดูรหัสผ่านผู้ดูแลระบบครั้งแรก
```

จากนั้นติดตั้ง [Caddy](https://caddyserver.com/docs/install) (หรือ nginx) ทำหน้าที่ HTTPS ส่งต่อมาที่ `127.0.0.1:3000`
ตัวอย่างไฟล์ `/etc/caddy/Caddyfile`:

```
helpdesk.mycompany.co.th {
	reverse_proxy 127.0.0.1:3000 {
		flush_interval -1
	}
}
```

(ถ้าใช้ nginx ต้องปิด buffering ของเส้นทาง `/api/v1/events`: `proxy_buffering off; proxy_read_timeout 1h;` ไม่เช่นนั้น real-time จะค้าง)

สำรองรายวันด้วย cron — สร้าง `/etc/cron.d/helpdesk-backup`:

```
0 2 * * * helpdesk DATA_DIR=/var/lib/helpdesk BACKUP_DIR=/var/backups/helpdesk /usr/bin/node --disable-warning=ExperimentalWarning /opt/helpdesk/scripts/backup.js
```

(ต้องสร้างโฟลเดอร์ `/var/backups/helpdesk` ให้ผู้ใช้ `helpdesk` เขียนได้ก่อน)
กู้คืนและรีเซ็ตรหัสผ่านใช้สคริปต์เดียวกัน: `sudo systemctl stop helpdesk` →
`sudo -u helpdesk env DATA_DIR=/var/lib/helpdesk node --disable-warning=ExperimentalWarning /opt/helpdesk/scripts/restore.js <ไฟล์>` → `sudo systemctl start helpdesk`

## ข้อจำกัดที่ควรรู้

- **เครื่องเดียว:** SQLite และ real-time (SSE) ทำงานในโปรเซสเดียว รันหลายเซิร์ฟเวอร์พร้อมกันไม่ได้ ถ้าองค์กรโตเกินนี้ต้องย้ายไป PostgreSQL
- **รูปแนบ** เก็บในฐานข้อมูล (ไม่เกิน 3 รูป/เรื่อง) ใช้งานนานฐานข้อมูลจะบวม ควรย้ายไปที่เก็บไฟล์แยกเมื่อมีตั๋วจำนวนมาก
- **ไม่มีอีเมลแจ้งเตือน/ลืมรหัสผ่านอัตโนมัติ** (ผู้ดูแลรีเซ็ตให้) และยังไม่มีการล็อกบัญชีเมื่อเดารหัสผิดหลายครั้ง (มีเพียงจำกัด 10 ครั้ง/นาที/IP)
- **หน้าแจ้งซ่อมสาธารณะ** กันสแปมด้วยการจำกัดต่อ IP และช่อง honeypot ถ้าเปิดให้คนทั่วโลกใช้และเจอการรบกวน ควรเพิ่ม CAPTCHA หรือปิดด้วย `ALLOW_GUEST=0`
